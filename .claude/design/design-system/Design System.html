Usage · 3 canonical calls
import "./confirm-dialog.jsx";
const { ConfirmDialog } = window;

// Variant 1 — Remove user
<ConfirmDialog
  title="Remove access?"
  tone="destructive"
  icon={<UserMinusIcon size={28}/>}
  entityPreview={
    <>
      <Avatar name="Artem Loban" size={36}/>
      <div>
        <div className="name">Artem Loban</div>
        <div className="meta">artem@example.com · Editor</div>
      </div>
    </>
  }
  description={<>Remove <strong>Artem Loban</strong> from <strong>Home apartment</strong>?</>}
  secondaryText="They will immediately lose access to this property and all its data. This can be undone by inviting them again."
  confirmLabel="Remove access"
  onConfirm={handleRemove}
  onCancel={closeModal}
/>

// Variant 2 — Hard-delete property
<ConfirmDialog
  title="Delete property permanently"
  tone="destructive"
  icon={<AlertTriangle size={28}/>}
  description={<>You're about to permanently delete <strong>Old apartment</strong>. This removes 3 services, 47 readings, 18 bills, and 14 payments forever.</>}
  warningText="This cannot be undone."
  requireType="DELETE"
  confirmLabel="Delete permanently"
  confirmIcon={<TrashIcon size={14}/>}
  onConfirm={handleHardDelete}
/>

// Variant 3 — Warning alert (single action)
<ConfirmDialog
  title="Can't leave as the last owner"
  tone="warning"
  icon={<AlertCircle size={28}/>}
  description={<>Every property needs at least one owner. You're currently the only owner of <strong>Home apartment</strong>.</>}
  secondaryText="To leave, promote someone else to Owner first, or delete the property if it's no longer needed."
  confirmLabel="Got it"
  cancelLabel={null}
  onConfirm={closeModal}
/>
Rules
  • One recipe, three tones. Never invent a new modal shell for a new kind of confirmation. Pick a tone, pass an icon.
  • Title is a question or imperative. "Remove access?" · "Delete property permanently". Sentence case. No "Are you sure".
  • Confirm button label is the verb. "Delete permanently", not "OK" or "Yes". Echoes the title.
  • requireType only above an irreversible threshold. Use for hard-delete; do not use for "Remove user", "Discard draft", or anything reversible.
  • Cancel sits left, confirm sits right. Spacing space-between. The destructive action is always the right-most button.
  • Single-action alerts (variant 3) use cancelLabel={null} and a primary-coloured confirm — the user is being told something, not asked.
  • Width 460. Don't exceed 520. If you need more, you're building a form, not a confirm.

Landing chrome — distinctives

What's different from the app.

  • Container. 1100px max (vs 1360px in CRM). Tighter, magazine-like.
  • Header height. 56px (vs 64px).
  • Hero glow. A radial violet gradient at rgba(124,58,237,0.10) in the top-right corner — only here.
  • Hero eyebrow pill. Violet text on rgba(124,58,237,0.08) background, violet border.
  • Section spacing. 72–96px vertical padding between sections (vs 20–32px stacked in app).
  • Display type. Up to 56px for the h1 — never used in app.
  • Sticky header on scroll. Becomes translucent (rgba(255,255,255,0.88) + blur(12px)).
  • Tech chips. Public Project page uses pill chips (radius 6, no fill) — Landing-only pattern.

CRM chrome — distinctives

The canonical user app surface — everything else is a delta against this.

  • Background. #ffffff page, #ffffff cards, #fafafa reserved for subtle row hover.
  • Top bar. 64px, sticky, translucent rgba(255,255,255,0.8) + blur 8.
  • Active nav. Violet underline 2px at bottom: -1.
  • Card. White, border #e4e4e7, radius 8, shadow 0 1px 2px rgba(24,24,27,.05).
  • Avatar. Violet tint background, violet text initials. Settings 7c moved to #ddd6fe avatar — slight drift.
  • Numbers. Always tabular (font-feature-settings: "tnum" 1).
  • Empty states. Big icon (40px), title 16, body 13.5 muted, CTA below.

Admin chrome — distinctives

A thin set of overrides on top of CRM. Same components, never duplicated.

  • Amber line. 3px solid #f59e0b at the very top — the only constant signal you are in admin.
  • Admin pill. Next to logo. Outline only (1.5px amber border, amber text, no fill) in light. Tinted fill in dark.
  • Logo mark. Switches from violet to foreground (black/white) — so the violet brand mark doesn't compete with the amber chrome.
  • Avatar. Amber tint (#fef3c7 / #fde68a).
  • Page background. #fafafa instead of pure white.
  • Active nav underline. Amber (#d97706) instead of violet.
  • Dark admin background. Deeper than user-dark — #050507 page over #18181b cards.
  • Role badges. Owner stays violet (it's a permission, not a chrome signal). Admin uses amber outline pill.
